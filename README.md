# 足球赛果图编辑器

独立开发的静态网页，支持赛事与报名名单、比赛事件、本场号码及历史号码、首发与守门员、实时赛果图预览，以及 PNG / SVG 导出。

- 在线使用：https://zajuak.github.io/match-editor/
- GitHub 仓库：https://github.com/zajuak/match-editor
- 个人网站旧链接：https://zajuak.github.io/tools/match-editor/（跳转到独立版本）

## 本地开发

使用 Node.js 24，无第三方 npm 依赖。

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:4323/ 。修改文件后刷新页面。

```sh
npm test
npm run build
npm run preview
```

构建产物为 `dist/`；预览默认也使用 4323 端口。指定其他端口：`npm run dev -- --port 4324`。

## 目录

- `src/index.html`：编辑界面。
- `src/editor.mjs`：界面交互、本地草稿、下载。
- `src/core.mjs`：球员身份、草稿迁移、号码、计分和 SVG 渲染。
- `src/importers.mjs`：官方名单与 Word 报名表解析。
- `src/editor.css`：样式。
- `src/data/`：公开赛事配置和精简名单。
- `src/SMC_files/`、`src/vendor/`：图标和 fflate 及其许可证。
- `scripts/`：开发服务器、静态构建、报名表转换脚本。
- `tests/`：编辑器回归检查和独立构建检查。

## 当前功能

1. 页面自动加载官方名单。当前 `2026年新生杯男子足球赛` 为 18 支球队、491 名球员；`2026-27北大杯女子足球赛` 为 8 支球队、135 名球员。女足赛事不录入或展示首发阵容，也无需指定首发守门员；从报名名单选择事件球员，在“本场号码”填写参与事件的球员号码，可沿用历史号码。选择赛事后，主客队列表仅显示该赛事球队。
2. 在“首发与本场号码”填写号码、勾选首发，双方各从本队首发中选择一名守门员。赛果图中双方守门员各排在本队首发第一位，姓名显示为“姓名(GK)”，其余球员保留勾选顺序。守门员号码可留空，无号码时号码位置显示 GK；守门员参与事件时同样无需号码。其他球员仍需号码，有号码的守门员仍受同队号码唯一性检查。球员旁显示上一次号码，可点击“沿用”。新比赛需重新指定守门员，本场号码为空，本场修改不会覆盖上次参考。
3. “自定义比赛”支持填写双方队名及首发，每行使用“号码 姓名”或纯姓名。输入球员全部成为首发，应用后才进入事件名单；重新应用会清空当前事件。未应用的修改会阻止添加事件和导出，避免导出旧内容。官方名单加载失败时，自定义比赛仍可保存和导出。
4. 添加事件直接选择球员；换人可成对添加，批量输入支持姓名或本场号码。同一时间的事件可拖动或用 ↑ ↓ 调序。改号码后事件与首发仍关联同一球员。
5. 比分根据事件计算；乌龙球选择造成乌龙的球员所属球队，给对方加分。时间 `点` 表示点球大战，比分单列。
6. 导出 PNG（通常为 1600px 宽）或自包含 SVG，图标题居中显示。导出前必须为双方各指定一名首发守门员，并补齐图中非守门员的号码。自定义比赛先应用首发，再选择守门员。取消守门员的首发资格或清空首发，会同步清除对应守门员选择。特别长的图片会降低 PNG 倍率，可优先使用 SVG。

比赛草稿与历史号码保存在当前浏览器 localStorage，不上传服务器，没有跨设备同步。官方名单以发布的数据为准，旧手工名单不会自动恢复；仍在官方名单中的球员、首发、事件和号码会保留，已经移除的记录会清理。

## 更新报名名单

原始 Word 报名表可能含手机号、球员身份和备注，必须留在仓库外。仓库只发布球队、球员姓名，不包含原始 DOCX。

本机原始文件仍在 `../赛果图编辑器/data/`。修改该目录的 `manifest.json` 或更新报名表后运行：

```sh
python3 scripts/prepare-match-rosters.py ../赛果图编辑器/data/manifest.json src/data
npm test
```

也可以将原始资料保存在其他本地目录，使用上述脚本的第一个参数指定清单路径。脚本支持新生杯双栏报名表及女足六列表格，并应用队名和姓名更正。人数变化时请同步更新完整性测试。

如需在浏览器直接解析本地原始清单，可将资料放在被 Git 忽略的目录，并自行运行仅供本机使用的服务；日常开发使用 `src/data/` 的精简 JSON。

## 部署

向 `main` 推送后，GitHub Actions 自动执行测试、构建并发布到 GitHub Pages。Pull request 只检查，不部署。

构建为脚本和样式生成内容版本号；修改前端代码后，浏览器会请求新资源。页面与数据使用相对路径，可以部署在 `/match-editor/` 或其他目录下。

个人网站仅保留入口和旧地址跳转。后续编辑器功能开发、名单更新、测试与发布均在本仓库完成，不再维护网站中的代码副本。
