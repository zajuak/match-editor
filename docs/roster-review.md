# 共享名单管理检查记录

检查日期：2026-11-10。

采用 GitHub Pages + Cloudflare Worker + D1，与积分榜使用同类架构。前台默认读取随 GitHub Pages 发布的名单快照，不自动访问 Cloudflare；主动同步和后台维护才连接 API。赛事、球队和球员管理已完成本地及线上数据库接入；生产 API 为 https://match-editor-api.junkaizhao404.workers.dev ，数据库为独立的 match-editor-rosters。

检查与修复：

- 修改权限由 Worker 校验管理员会话；密码使用 PBKDF2 哈希保存在 Worker Secret，前端不包含管理员密钥。
- 会话使用随机令牌，数据库只存令牌哈希；8 小时过期，退出立即失效，更换密码哈希会撤销所有旧会话。错误登录限流。
- 名单修改使用 revision 乐观并发检查；同一事务更新版本和业务数据，冲突或约束错误不会部分保存。
- 排序使用单个数据库事务，规范化重复位置，并验证同一上级。
- 后台最新数据缓存到当前浏览器，编辑器返回或收到同源缓存更新时使用新名单；其他设备可主动同步。旧静态版本不能覆盖较新的缓存；更新失败保留当前比赛。
- 保留现有 2 个赛事、26 支球队、626 名球员的 UUID 和 legacy_key，支持旧草稿及后续改名。
- 删除后重建的同名赛事、球队不会误接回旧草稿；管理员自定义名称不会被旧静态别名覆盖。
- 首次导入只允许空名单数据库，不会覆盖已有后台修改。

验证结果：

- 71 项自动化测试通过，包含编辑器旧功能、草稿迁移、Worker 权限、SQLite 事务、并发冲突、登录过期及撤销。
- 后台 DOM 联动测试覆盖登录、增删改、排序、退出和名称转义；编辑器 DOM 测试覆盖共享名单加载、改名后的草稿恢复、领队选项和 SVG 导出。
- 实际本地 Worker/D1 已验证名单导入、增删改、排序、级联删除，并在测试后恢复至 626 名球员。
- 生产 API 验证名单数量、原有 UUID、匿名修改拒绝、管理员登录和退出。
- 原有本地 PostgreSQL 数据保持完整，未删除旧数据库。
- 浏览器自动化服务连接超时，未完成本次界面截图、移动端布局及 PNG 导出的视觉实测；DOM 测试不能替代视觉检查。
